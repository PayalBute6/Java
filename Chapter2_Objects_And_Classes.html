2.1 Introduction

2.1.1 Java and Object-Oriented Programming

Java is an Object-Oriented Programming (OOP) language. In Java, objects and classes are the basic building blocks of Object-Oriented Programming. Everything that we represent in Java is associated with classes and objects.

In Object-Oriented Programming, we represent real-world entities using objects. For example:

  • Student
  • Employee
  • Car
  • Bank Account
  • Customer
  • Book

All of these can be represented as objects in Java.

State and Behavior

Every real-world object generally has two important characteristics:

1. State

State represents the data or characteristics of an object.

For example, a Car can have state attributes such as Color, Model, Brand, Price, Speed. A Student can have Roll number, Name, Age, and Course.

2. Behavior

Behavior represents the actions or operations that an object can perform.

For example, a Car performs actions like Start, Stop, Accelerate, Brake. A Student performs actions like Study, AttendLecture, WriteExam.

💡 Key Principle:
State represents what an object HAS, whereas behavior represents what an object DOES.

Object in Java

Definition: A real-world entity that has state and behavior is known as an object.
Simple Definition for Examination: An object is an instance of a class.

Class in Java

Definition: A class is a template or blueprint that describes the states and behaviors supported by objects of its type.
Class Student │ ┌───────┴───────┐ │ │ Object Object Student 1 Student 2

Difference Between Class and Object

Class Object
Class is a blueprint/template. Object is an instance of a class.
It defines state and behavior. It represents actual state and behavior values.
Objects are created from a class. Object is created using the class template.
Example: Student Example: s1, s2
Logical representation (occupies no heap memory for data) Real/actual representation (occupies heap memory)

Unit 2.2

2.2 Defining Your Own Classes

Java allows programmers to create their own classes according to application requirements. A class contains data members/variables, methods, and constructors.

General Syntax of a Class

class ClassName
{
    // Fields declaration
    accessSpecifier dataType variable;

    // Methods declaration
    accessSpecifier returnType methodName()
    {
        // body of method
    }
}

Methods in Java

A method is a collection of statements grouped together to perform a particular task. Methods avoid redundant code and promote reusability.

2.2.1 Creating Objects (3 Steps)

An object is created using the new keyword.

  1. Declaration: A reference variable is declared (Student s1;).
  2. Instantiation: The new keyword allocates memory for the object in heap memory (new Student()).
  3. Initialization: The constructor initializes the newly created object.
Declaration ──► Student s1; │ Instantiation ──► new Student(); (Heap Memory Allocated) │ Initialization──► Constructor invoked

2.2.2 Accessing Class Members

Members are accessed using the dot (.) operator (syntax: objectName.memberName;).

Unit 2.3

2.3 Access Specifiers

Java provides 4 access specifiers to restrict visibility and enforce encapsulation:

  • Private: Accessible ONLY inside the same class. Accessor (Getter) reads private values, Mutator (Setter) modifies them safely.
  • Default (Package-private): Accessible by classes in the same package when no modifier is specified.
  • Protected: Accessible within the same class, same package, and by subclasses in other packages through inheritance.
  • Public: Accessible from anywhere across all packages.

Access Specifier Comparison Table

Access Modifier Same Class Same Package Subclass (Diff Pkg) Outside Package
private ✓ ✗ ✗ ✗
default ✓ ✓ ✗ ✗
protected ✓ ✓ ✓ (via inheritance) ✗
public ✓ ✓ ✓ ✓

Unit 2.4

2.4 Array of Objects

An array of objects stores references to objects of a particular class rather than primitive values directly.

Writing Employee emp[] = new Employee[3]; only creates an array container holding 3 null references. Objects must be created separately:

Initially (Array of references): emp ──► [ null , null , null ] After Object Instantiation: emp ──► [ Employee Object 1 , Employee Object 2 , Employee Object 3 ]

Complete Program Example:

class Employee
{
    int id;
    String name;

    public void setData(int id, String name)
    {
        this.id = id;
        this.name = name;
    }

    public void display()
    {
        System.out.println("Employee id: " + this.id + ", name: " + this.name);
    }

    public static void main(String[] args)
    {
        Employee emp[] = new Employee[3];

        emp[0] = new Employee();
        emp[1] = new Employee();
        emp[2] = new Employee();

        emp[0].setData(1, "Amit");
        emp[1].setData(2, "Akash");
        emp[2].setData(3, "Akbar");

        for(Employee e : emp) {
            e.display();
        }
    }
}
Output:
Employee id: 1, name: Amit
Employee id: 2, name: Akash
Employee id: 3, name: Akbar

Unit 2.5

2.5 Constructors and Overloading Constructors

A constructor is a special method used to initialize an object automatically when it is created using new.

Constructor vs Method Comparison Table

Constructor Method
Used to initialize an object. Used to perform a specific task/action.
Must have the exact same name as the class. Can have any valid identifier name.
Has no return type (not even void). Must specify a return type (or void).
Automatically invoked during object creation. Invoked explicitly via object or class reference.

Textbook Constructor Rules

  1. Constructor name must match class name exactly.
  2. Constructor cannot have a return type (adding void turns it into a method).
  3. Constructor access modifier can be private, protected, or public.

Types of Constructors

1. Default Constructor

A constructor that does not take any parameters is called a default constructor.

class Student
{
    int rollNo;
    String name;

    Student()
    {
        rollNo = 101;
        name = "Amit";
    }

    void display()
    {
        System.out.println("Roll No: " + rollNo + ", Name: " + name);
    }

    public static void main(String[] args)
    {
        Student s = new Student();
        s.display();
    }
}
Output:
Roll No: 101, Name: Amit

2. Parameterized Constructor

A constructor that accepts parameters is called a parameterized constructor. It allows passing different initial values for different objects.

class Student
{
    int rollNo;
    String name;

    Student(int r, String n)
    {
        rollNo = r;
        name = n;
    }

    void display()
    {
        System.out.println("Roll No: " + rollNo + ", Name: " + name);
    }

    public static void main(String[] args)
    {
        Student s1 = new Student(101, "Amit");
        Student s2 = new Student(102, "Rahul");

        s1.display();
        s2.display();
    }
}
Output:
Roll No: 101, Name: Amit
Roll No: 102, Name: Rahul
💡 Why use a Parameterized Constructor?
Instead of writing hardcoded assignments inside the class for every student, parameterized constructors allow passing custom values during object creation so that each object gets its own initial state (`Student s1 = new Student(101, "Amit");`).

Textbook Concept Example (Marks Calculation)

class Student
{
    int rollNo;
    int marks1, marks2;

    Student(int roll_no, int m1, int m2)
    {
        rollNo = roll_no;
        marks1 = m1;
        marks2 = m2;
    }

    int getTotal() { return marks1 + marks2; }

    void displayResult()
    {
        System.out.println("Roll No: " + rollNo + " | Total: " + getTotal());
    }
}

Constructor Overloading

Defining multiple constructors in the same class with different parameter lists is known as constructor overloading.

class Student
{
    int id;
    String name;

    // 1. Default constructor
    Student()
    {
        id = 0;
        name = "Unknown";
    }

    // 2. Single-parameter constructor
    Student(int i)
    {
        id = i;
        name = "Unknown";
    }

    // 3. Two-parameter constructor
    Student(int i, String n)
    {
        id = i;
        name = n;
    }

    void display()
    {
        System.out.println("ID: " + id + ", Name: " + name);
    }

    public static void main(String[] args)
    {
        Student s1 = new Student();
        Student s2 = new Student(101);
        Student s3 = new Student(102, "Rahul");

        s1.display();
        s2.display();
        s3.display();
    }
}
Output:
ID: 0, Name: Unknown
ID: 101, Name: Unknown
ID: 102, Name: Rahul

5 Important Rules of Constructor Overloading:

  1. Constructors must have the same name as the class.
  2. Constructors must have different parameter lists (differ in number, type, or order of parameters).
  3. Constructors cannot have a return type.
  4. Constructors can be overloaded multiple times.
  5. The compiler determines which constructor to call based on the arguments passed during new.

Unit 2.6

2.6 'this' Keyword & Static Members

2.6.1 The `this` Keyword

this is a special keyword in Java that refers to the current object instance. In simple words: "this" means "the current object".

It resolves variable shadowing when instance variables and parameter names are identical:

class Student
{
    int roll;
    String name;

    Student(int roll, String name)
    {
        this.roll = roll;  // this.roll -> instance variable | roll -> parameter
        this.name = name;  // this.name -> instance variable | name -> parameter
    }
}

4 Primary Uses of `this` Keyword:

  1. Referring to current class instance variable (this.variable).
  2. Invoking current class method (this.method()).
  3. Invoking current class constructor (this()).
  4. Passing `this` as an argument to a method.

Constructor Chaining using `this()`

this() is used to invoke another constructor of the same class. It must be the first statement inside the constructor.

class Student
{
    int roll;
    String name;

    Student()
    {
        this(101, "Ram"); // Calls Student(int, String)
    }

    Student(int roll, String name)
    {
        this.roll = roll;
        this.name = name;
    }

    void display()
    {
        System.out.println(roll + " " + name);
    }

    public static void main(String[] args)
    {
        Student s = new Student();
        s.display();
    }
}
Output:
101 Ram
Execution Flow of this(): Student s = new Student(); ↓ Student() constructor invoked ↓ this(101, "Ram") statement executed ↓ Student(int roll, String name) parameterized constructor invoked ↓ Values assigned to instance fields

2.6.2 Static Members (Fields, Methods & Blocks)

The static keyword denotes members that belong to the class itself rather than individual object instances.

1. Static Field (Class Variable)

A variable declared as static belongs to the class and has a single shared copy across all instances.

Instance Variables (Separate memory per object): s1 ──► roll = 101, name = "Ram" s2 ──► roll = 102, name = "Amit" Static Variable (Single shared memory): college [ "ABC College" ] ↑ ---------------- | | | s1 s2 s3

2. Static Method

Invoked directly using the class name (ClassName.methodName()) without instantiating an object.

⚠️ Important Rule: A static method can directly access ONLY static data. It cannot access non-static instance variables directly because instance variables belong to objects!

3. Static Block

A static block is written as static { ... }. It is executed ONCE when the class is loaded into memory, before the main() method executes. Used for static variable initialization.

class Student
{
    int roll;
    String name;
    static String college = "ABC College";

    static {
        System.out.println("Static block executed.");
    }

    Student(int roll, String name)
    {
        this.roll = roll;
        this.name = name;
    }

    static void changeCollege()
    {
        college = "XYZ College";
    }

    void display()
    {
        System.out.println(roll + " " + name + " " + college);
    }

    public static void main(String[] args)
    {
        Student.changeCollege();

        Student s1 = new Student(101, "Prashant");
        Student s2 = new Student(102, "Rahul");

        s1.display();
        s2.display();
    }
}
Output:
Static block executed.
101 Prashant XYZ College
102 Rahul XYZ College

Instance vs Static Members Comparison

Instance Member Static Member
Belongs to an object instance. Belongs to the class.
Separate copy created for every object. Single shared copy across all objects.
Accessed using object reference (s1.roll). Accessed using Class Name (Student.college).
Created when object is instantiated. Associated with class when loaded into memory.

2.7 Predefined Classes (Object, String, StringBuffer & Formatting)

2.7.1 Object Class

java.lang.Object is the root class of all Java classes. Every Java class directly or indirectly inherits from Object.

Key Object Class Methods:

Method Purpose & Explanation
toString() Returns string representation of object. By default prints ClassName@hashcode. Overridden to produce readable details.
equals(Object obj) Compares object references by default. Overridden to compare content data of objects.
hashCode() Returns an integer hash value representing the object. Commonly used by hash collections like HashMap, HashSet.
getClass() Returns the runtime class metadata object (e.g. class Student).

StringBuffer represents a MUTABLE sequence of characters. Contents can be modified without creating new objects repeatedly.

StringBuffer Constructors:

  • StringBuffer(): Creates empty buffer with default capacity of 16 characters.
  • StringBuffer("Java"): Creates buffer containing specified string.
  • StringBuffer(20): Creates empty buffer with specified initial capacity.

9 Key StringBuffer Methods:

String is like writing on a permanent paper — you cannot modify existing text; you must take a new paper.
StringBuffer is like writing on a whiteboard — you can edit, erase, append, and modify existing content directly on the board!

String vs StringBuffer Comparison Table

Unit 2.8

2.8 Packages

A package is a collection of related classes and interfaces grouped together under a common name. It acts as a folder container in Java.

5 Key Benefits of Packages

  1. Avoid Name Conflicts: Allows classes in different packages to have identical names (e.g. college.Student vs school.Student).
  2. Organize Classes: Groups logically related classes into sub-folders.
  3. Control Access: Helps protect class visibility across package boundaries.
  4. Reusability: Classes inside a package can be easily reused in other programs.
  5. Easy Maintenance: Keeps large projects modular and easy to manage.

Types of Packages

  • Built-in / System Packages: Provided by Java platform (e.g. java.lang, java.util, java.io, java.net, java.awt).
  • User-Defined Packages: Packages created by programmers (e.g. package mypackage;).
Java Package Hierarchy: java ├── lang (Automatic import: String, Math, System, Object) ├── util (Scanner, ArrayList, Date) ├── io (BufferedReader, File) ├── net (Socket, URL) └── awt (Graphics, Component)

2.8.1 Creating User-Defined Packages

Use the package keyword as the first non-comment statement in the Java file.

// File: A.java
package mypackage;

public class A
{
    public void display()
    {
        System.out.println("Hello from mypackage.A!");
    }
}

Compiling Package File:

javac -d . A.java

The -d . option tells the compiler to create the mypackage folder directory automatically and save A.class inside it.

2.8.2 Accessing Packages & `import` Statement

Method 1: Using `import` Statement

import mypackage.A;    // Imports specific class A
import mypackage.*;    // Imports all public classes of mypackage

Method 2: Using Fully Qualified Class Name

Used without an import statement by writing full package path directly (essential when resolving name conflicts):

mypackage.A obj = new mypackage.A();

2.8.3 System Packages & `java.lang`

The java.lang package is automatically imported into every Java program. Classes like String, System, Math, Integer do NOT require an explicit import java.lang.*; statement.

2.8.4 Sub-packages

Packages can contain sub-packages to form deeper hierarchical folder structures (e.g. package college.student;).

2.9 Wrapper Classes

A wrapper class is a predefined Java class that wraps a primitive data type into an object (e.g. int → Integer).

Primitive Data Types and Wrapper Classes Table

Primitive Data Type Wrapper Class Conversion Method (Object → Primitive)
byte Byte byteValue()
short Short shortValue()
int Integer intValue()
long Long longValue()
float Float floatValue()
double Double doubleValue()
char Character charValue()
boolean Boolean booleanValue()
⭐ Exam Question Spotting:
Q. What is the wrapper class of `int`? → Integer
Q. What is the wrapper class of `char`? → Character

Why Do We Need Wrapper Classes?

  1. To convert primitive values into objects when methods or collections require objects.
  2. To convert objects back into primitive values.
  3. To convert Strings into numbers (e.g. Integer.parseInt("100")).
  4. To convert numbers into Strings (e.g. Integer.toString(100)).
  5. To provide utility functions for characters (e.g. Character.isDigit('5')).

Conversion Methods Summary

1. Primitive to Wrapper Object

int a = 10;
Integer obj = Integer.valueOf(a); // Explicit conversion

2. Wrapper Object to Primitive

Integer obj = Integer.valueOf(10);
int a = obj.intValue(); // Explicit unboxing

3. String to Primitive Parsing

int n = Integer.parseInt("141");
double d = Double.parseDouble("59.36");

4. Primitive/Number to String

String s1 = Integer.toString(141);
String s2 = Double.toString(59.36);

Autoboxing and Unboxing

  • Autoboxing: Automatic conversion of primitive type into wrapper object by Java compiler (Integer obj = 10;).
  • Unboxing: Automatic conversion of wrapper object into primitive type (int x = obj;).
💡 Boxing vs Unboxing Analogy:
Boxing means putting a primitive value inside a gift box (Object).
Unboxing means opening the gift box to take out the raw primitive value!

Complete Wrapper Demo Program:

class WrapperDemo
{
    public static void main(String[] args)
    {
        int n = 59;

        Integer obj = Integer.valueOf(n); // Primitive to Object
        System.out.println("Object value: " + obj);

        int x = obj.intValue();           // Object to Primitive
        System.out.println("Primitive value: " + x);

        int parsed = Integer.parseInt("100");
        System.out.println("Parsed value + 50: " + (parsed + 50));
    }
}
Output:
Object value: 59
Primitive value: 59
Parsed value + 50: 150
