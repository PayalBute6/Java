Chapter 3: Inheritance and Interfaces

3.1 Introduction to Inheritance

1. What is inheritance?

Inheritance is an Object-Oriented Programming (OOP) feature in which one class acquires accessible fields and methods from another class.

The existing class is called the parent class, base class, or superclass. The new class is called the child class, derived class, or subclass.

Inheritance helps us reuse code and organize related classes into a clear hierarchy.

Real-life example

Consider a general class called Vehicle. A Car and a Bike are both types of vehicles:

  • Vehicle contains common properties and behaviours (e.g. speed, fuel capacity, start, stop).
  • Car reuses the common features of Vehicle and defines its own features (e.g. air conditioning, number of doors).
  • Bike also reuses the common features and adds its own features (e.g. kick start, helmet storage).
            Vehicle (Parent / Superclass)
                    /        \
                   /          \
      Car (Child class)    Bike (Child class)

2. Advantages of inheritance

  1. Code reusability: Common code can be written once in the parent class.
  2. Less duplication: Child classes reuse inherited functionality instead of rewriting code.
  3. Easy maintenance: Common behaviour can be updated or fixed in one central place.
  4. Extensibility: Child classes can easily add specialized fields and methods.
  5. Polymorphism: Inheritance supports runtime polymorphism through method overriding.

3. Basic syntax

class Parent {
    // Fields and methods
}

class Child extends Parent {
    // Additional fields and methods
}

The keyword extends establishes class inheritance.

4. First inheritance program

class Animal {
    void eat() {
        System.out.println("Animal is eating.");
    }
}

class Dog extends Animal {
    void bark() {
        System.out.println("Dog is barking.");
    }
}

public class Main {
    public static void main(String[] args) {
        Dog d = new Dog();

        d.eat();
        d.bark();
    }
}

Output:

Animal is eating.
Dog is barking.

Program explanation

  • Animal is the superclass.
  • Dog is the subclass.
  • extends Animal allows Dog to inherit accessible members of Animal.
  • eat() is defined in Animal.
  • bark() is defined in Dog.
  • The object d can invoke both the inherited method eat() and its own method bark().
Remember: Inheritance does not mean that the child class can directly access every member of the parent. Access depends strictly on the member's access modifier (e.g., private members cannot be accessed directly).

3.2 Basic Terminology and the extends Keyword

Important terms

Term Meaning
Superclass The class being inherited from (Parent or Base class).
Subclass The class that inherits from another class (Child or Derived class).
extends Keyword used for class inheritance.
Inherited member An accessible field or method obtained from the superclass.
IS-A relationship A relationship in which the subclass represents a more specific type of the superclass.

Example of an IS-A relationship

A Dog IS-A Animal.

class Animal {
}

class Dog extends Animal {
}

A Dog object can be assigned to an Animal reference variable:

Animal a = new Dog();

This is valid because Dog is a subclass of Animal.

However, the reverse assignment (Dog d = new Animal();) is not valid without an explicit cast, and that cast is safe only when the actual object at runtime is indeed a Dog.

Important point about constructors

Constructors are not inherited by subclasses. When a subclass object is created, a superclass constructor is invoked first as part of object construction.

class Parent {
    Parent() {
        System.out.println("Parent constructor");
    }
}

class Child extends Parent {
    Child() {
        System.out.println("Child constructor");
    }
}

class Main {
    public static void main(String[] args) {
        new Child();
    }
}

Output:

Parent constructor
Child constructor

The superclass constructor executes before the subclass constructor body runs.

3.3 Types of Inheritance

Inheritance can be classified according to how classes are hierarchically related.

1. Single inheritance

One subclass inherits directly from one superclass.

A (Parent)
    │
    ▼
B (Child)
class A {
    void showA() {
        System.out.println("Class A");
    }
}

class B extends A {
    void showB() {
        System.out.println("Class B");
    }
}

class Main {
    public static void main(String[] args) {
        B obj = new B();
        obj.showA();
        obj.showB();
    }
}

Output:

Class A
Class B

2. Multilevel inheritance

A class inherits from a class that itself inherits from another class.

A
│
▼
B extends A
│
▼
C extends B
class A {
    void displayA() {
        System.out.println("Class A");
    }
}

class B extends A {
    void displayB() {
        System.out.println("Class B");
    }
}

class C extends B {
    void displayC() {
        System.out.println("Class C");
    }
}

class Main {
    public static void main(String[] args) {
        C obj = new C();
        obj.displayA();
        obj.displayB();
        obj.displayC();
    }
}

Output:

Class A
Class B
Class C

Class C can access the accessible inherited methods from both B and A.

3. Hierarchical inheritance

Two or more subclasses inherit from the same superclass.

          Animal
          /    \
         /      \
       Dog      Cat
class Animal {
    void eat() {
        System.out.println("Animal eats food.");
    }
}

class Dog extends Animal {
    void bark() {
        System.out.println("Dog barks.");
    }
}

class Cat extends Animal {
    void meow() {
        System.out.println("Cat meows.");
    }
}

class Main {
    public static void main(String[] args) {
        Dog d = new Dog();
        Cat c = new Cat();

        d.eat();
        d.bark();

        c.eat();
        c.meow();
    }
}

Output:

Animal eats food.
Dog barks.
Animal eats food.
Cat meows.

4. Multiple inheritance

Multiple inheritance means inheriting from more than one parent class.

Java does not support multiple inheritance with classes. A class cannot directly extend two classes to avoid ambiguity (the Diamond Problem).

// Invalid in Java: A class cannot extend two classes
class C extends A, B { // Compile-time error
}

However, Java supports multiple inheritance of type through interfaces:

interface Printable {
    void print();
}

interface Showable {
    void show();
}

class Demo implements Printable, Showable {
    public void print() {
        System.out.println("Printing");
    }

    public void show() {
        System.out.println("Showing");
    }
}

5. Hybrid inheritance

Hybrid inheritance combines two or more inheritance patterns. Java does not support hybrid inheritance through classes alone, but combinations can be created using interfaces.

Summary of inheritance types

Type Supported in Java?
Single Yes, using classes (class B extends A).
Multilevel Yes, using classes (class C extends B where B extends A).
Hierarchical Yes, using classes (multiple classes extend one superclass).
Multiple Not through classes; fully supported through interfaces.
Hybrid Possible in supported combinations using classes and interfaces.

3.4 Accessing Superclass Members

A subclass can access superclass members according to their access modifiers:

Modifier Access from subclass in another package?
public Yes, accessible from any class.
protected Yes, accessible in subclasses in any package through inheritance.
Default (package-private) No, accessible only within the same package.
private No direct access; accessible only within its declaring class.

Example: Access modifiers in inheritance

class Parent {
    public int a = 10;
    protected int b = 20;
    int c = 30;
    private int d = 40;
}

class Child extends Parent {
    void display() {
        System.out.println(a); // Accessible
        System.out.println(b); // Accessible
        System.out.println(c); // Accessible (same package)

        // System.out.println(d); // Compile-time error: d has private access
    }
}

class Main {
    public static void main(String[] args) {
        Child obj = new Child();
        obj.display();
    }
}

Output (when all classes are in the same package):

10
20
30

The private member d is not directly accessible in Child. It can only be accessed through public or protected getter/setter methods in Parent.

Teaching point: A subclass object contains the superclass portion in memory, but access modifiers still strictly control which members the subclass can reference directly.

3.5 The super Keyword

The super keyword refers to the immediate superclass part of the current object. It is commonly used to access superclass members and constructors.

Primary uses of super

  1. Access a superclass field when shadowed by a subclass field.
  2. Invoke a superclass method that has been overridden in the subclass.
  3. Invoke a superclass constructor.

1. Accessing a superclass field

class Parent {
    int x = 10;
}

class Child extends Parent {
    int x = 20;

    void display() {
        System.out.println("Child x = " + x);
        System.out.println("Parent x = " + super.x);
    }
}

class Main {
    public static void main(String[] args) {
        Child obj = new Child();
        obj.display();
    }
}

Output:

Child x = 20
Parent x = 10

2. Calling a superclass method

class Parent {
    void display() {
        System.out.println("Parent method");
    }
}

class Child extends Parent {
    void display() {
        System.out.println("Child method");
        super.display(); // Calls Parent's display method
    }
}

class Main {
    public static void main(String[] args) {
        Child obj = new Child();
        obj.display();
    }
}

Output:

Child method
Parent method

3. Calling a superclass constructor

class Parent {
    Parent(String name) {
        System.out.println("Parent: " + name);
    }
}

class Child extends Parent {
    Child() {
        super("Java"); // Explicit call to superclass constructor
        System.out.println("Child constructor");
    }
}

class Main {
    public static void main(String[] args) {
        new Child();
    }
}

Output:

Parent: Java
Child constructor

Important rules for super(...)

  • A constructor call using super(...) invokes the matching superclass constructor.
  • When explicitly used, super(...) must be the first statement in the constructor body.
  • If no superclass constructor call is written, Java automatically inserts super() with no arguments. This requires an accessible no-argument constructor in the superclass.

3.6 Method Overriding

Definition

Method overriding occurs when a subclass provides its own specific implementation of an instance method that is already defined in its superclass, using an identical method name, return type, and parameter list.

Overriding allows a subclass to customize or replace the default behaviour of its parent class.

Example

class Animal {
    void sound() {
        System.out.println("Animal makes a sound.");
    }
}

class Dog extends Animal {
    @Override
    void sound() {
        System.out.println("Dog barks.");
    }
}

class Main {
    public static void main(String[] args) {
        Dog d = new Dog();
        d.sound();
    }
}

Output:

Dog barks.

Rules of method overriding

  1. The method must be inherited from a superclass.
  2. The method signature (name and parameter types) must match exactly.
  3. The return type must be the same, or covariant (a subclass type) for reference types.
  4. The overriding method cannot reduce the access level (e.g., if parent method is protected, child cannot make it private).
  5. private methods cannot be overridden because they are not visible to subclasses.
  6. static methods cannot be overridden; they are hidden (method hiding).
  7. final methods cannot be overridden.
  8. The @Override annotation ensures compile-time validation that overriding rules are met.

Method overloading vs. method overriding

Method Overloading Method Overriding
Same method name with different parameter lists. Same method name and exact same parameter list.
Can occur within a single class. Requires an inheritance relationship between classes.
Compile-time polymorphism (Static binding). Runtime polymorphism (Dynamic binding).
Return type can be different. Return type must be identical or covariant.
Example: add(int, int) and add(double, double). Example: Animal.sound() and Dog.sound().

3.7 Dynamic Method Dispatch

Dynamic method dispatch is the runtime mechanism by which an invocation of an overridden instance method is resolved at runtime based on the actual object being referenced, rather than the reference variable's declared type.

It is the core foundation of runtime polymorphism in Java.

Example: Dynamic dispatch

class Animal {
    void sound() {
        System.out.println("Animal sound");
    }
}

class Dog extends Animal {
    @Override
    void sound() {
        System.out.println("Dog barks");
    }
}

class Cat extends Animal {
    @Override
    void sound() {
        System.out.println("Cat meows");
    }
}

class Main {
    public static void main(String[] args) {
        Animal a; // Superclass reference variable

        a = new Dog(); // Refers to Dog object
        a.sound();     // Calls Dog's sound()

        a = new Cat(); // Refers to Cat object
        a.sound();     // Calls Cat's sound()
    }
}

Output:

Dog barks
Cat meows

Explanation

  • Animal a declares a superclass reference variable.
  • a = new Dog() assigns a Dog object to a. When a.sound() is executed, the JVM checks the actual object type (Dog) and runs Dog's version.
  • a = new Cat() assigns a Cat object. The next call invokes Cat's version.

3.8 Abstract Classes and Abstract Methods

1. What is an abstract class?

An abstract class is a class declared with the abstract modifier. It serves as a base blueprint for subclasses and cannot be instantiated directly with new.

An abstract class can contain both abstract methods (without body) and concrete methods (with body).

2. What is an abstract method?

An abstract method is a method declared without an implementation (without curly braces), ending with a semicolon:

abstract void calculateArea();

Concrete subclasses are required to provide the implementation for all inherited abstract methods.

3. Example program: Abstract Shape class

abstract class Shape {
    abstract void calculateArea(); // Abstract method
}

class Rectangle extends Shape {
    int length = 10;
    int breadth = 5;

    @Override
    void calculateArea() {
        System.out.println("Rectangle area = " + (length * breadth));
    }
}

class Circle extends Shape {
    double radius = 7;

    @Override
    void calculateArea() {
        System.out.println("Circle area = " + (Math.PI * radius * radius));
    }
}

class Main {
    public static void main(String[] args) {
        Shape s;

        s = new Rectangle();
        s.calculateArea();

        s = new Circle();
        s.calculateArea();
    }
}

Output:

Rectangle area = 50
Circle area = 153.93804002589985

4. Important points about abstract classes

  1. An abstract class cannot be directly instantiated (cannot write new Shape()).
  2. An abstract class can have constructors, which run when a subclass object is created.
  3. An abstract class can contain instance variables, static variables, and constants.
  4. It can contain both abstract and concrete methods.
  5. A concrete subclass must implement all inherited abstract methods unless the subclass itself is declared abstract.
  6. An abstract class can extend another class and implement interfaces.

3.9 Interfaces in Java

1. What is an interface?

An interface is a pure blueprint of a class that defines a contract of methods that implementing classes must follow. It is used to achieve total abstraction and to support multiple inheritance of type in Java.

2. Syntax of an interface

interface Printable {
    void print(); // Implicitly public abstract
}

class Document implements Printable {
    public void print() {
        System.out.println("Printing document");
    }
}

3. Example program

interface Animal {
    void sound();
}

class Dog implements Animal {
    public void sound() {
        System.out.println("Dog barks");
    }
}

class Cat implements Animal {
    public void sound() {
        System.out.println("Cat meows");
    }
}

class Main {
    public static void main(String[] args) {
        Animal a = new Dog();
        a.sound();

        a = new Cat();
        a.sound();
    }
}

Output:

Dog barks
Cat meows

4. Important rules of interfaces

  1. An interface cannot be instantiated directly.
  2. A class implements an interface using the implements keyword.
  3. A class can implement multiple interfaces separated by commas (implements A, B).
  4. A class can extend one superclass and implement multiple interfaces simultaneously: 
    class C extends Parent implements A, B
  5. All fields in an interface are implicitly public static final constants.
  6. All abstract methods in an interface are implicitly public abstract.
  7. Modern Java (Java 8+) permits default and static methods with bodies, and Java 9+ permits private helper methods in interfaces.

Multiple interfaces example

interface Printable {
    void print();
}

interface Showable {
    void show();
}

class Demo implements Printable, Showable {
    public void print() {
        System.out.println("Print method");
    }

    public void show() {
        System.out.println("Show method");
    }
}

class Main {
    public static void main(String[] args) {
        Demo d = new Demo();
        d.print();
        d.show();
    }
}

Output:

Print method
Show method

3.10 Types of Interfaces

1. Normal interface

A normal interface declares multiple abstract methods.

interface Calculator {
    int add(int a, int b);
    int subtract(int a, int b);
}

2. Marker interface

A marker interface (also called a tagging interface) contains no methods or constants. It simply marks a class as having a specific property or capability for the JVM or compiler.

Standard Java examples: Serializable, Cloneable, Remote.

import java.io.Serializable;

class Student implements Serializable {
    int id;
    String name;
}

3. Functional interface

A functional interface contains exactly one abstract method. It can be annotated with @FunctionalInterface and can be implemented concisely using Lambda expressions (Java 8+).

@FunctionalInterface
interface Greeting {
    void sayHello();
}

class Main {
    public static void main(String[] args) {
        // Implementing functional interface using Lambda expression
        Greeting g = () -> System.out.println("Hello Students!");

        g.sayHello();
    }
}

Output:

Hello Students!

3.11 Abstract Class vs. Interface

Abstract Class Interface
Declared using the abstract class keyword. Declared using the interface keyword.
A class inherits it using extends. A class implements it using implements.
Can have instance variables and constants. Can only have public static final constants.
Can have constructors. Cannot have constructors.
Can contain abstract and concrete methods. Contains abstract methods (and default/static methods in Java 8+).
A class can extend only one abstract class (Single inheritance). A class can implement multiple interfaces (Multiple inheritance).
Best for sharing code and state among closely related classes. Best for defining standard contracts among unrelated classes.

3.12 The final Keyword in Inheritance

The final keyword is used to restrict inheritance, overriding, and reassignment:

1. Final class

A final class cannot be extended by any subclass:

final class A {
}

// class B extends A { } // Compile-time error: cannot inherit from final A

2. Final method

A final method cannot be overridden by a subclass:

class Parent {
    final void display() {
        System.out.println("Parent display");
    }
}

class Child extends Parent {
    // void display() { } // Compile-time error: cannot override final method
}

3. Final variable

A final variable acts as a constant and cannot be reassigned after initialization:

final int MAX = 100;
// MAX = 200; // Compile-time error: cannot assign a value to final variable MAX
Remember: final class prevents inheritance, final method prevents overriding, and final variable prevents reassignment.
