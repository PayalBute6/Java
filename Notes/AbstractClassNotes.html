Understanding Abstract Classes

A comprehensive guide to abstract classes and methods in Java.

1. Use of Abstract Class

An abstract class is mainly used as a base class for other classes.

Main uses:

1. To provide a common base for subclasses

Suppose we have different banks:

Bank (Abstract Class) / \ / \ SBI PNB

Both SBI and PNB are banks. So we can create a common abstract class:

abstract class Bank {
    abstract int getRateOfInterest();
}

Then:

class SBI extends Bank {
    int getRateOfInterest() {
        return 7;
    }
}

class PNB extends Bank {
    int getRateOfInterest() {
        return 8;
    }
}

Here, Bank provides the common structure, while SBI and PNB provide their own specific implementations.

2. To prevent object creation of the base class

An abstract class cannot be instantiated.

For example:

abstract class Bank {
}

We cannot write:

Bank b = new Bank();   // ❌ Error: Bank is abstract

Why?

Because Bank is only a general concept. We want objects of specific banks such as SBI or PNB.

SBI s = new SBI();     // ✅ Correct
PNB p = new PNB();     // ✅ Correct
From the lab book: An abstract class is defined as a class that cannot be instantiated and is used to create subclasses.

3. To achieve abstraction

An abstract class allows us to specify what a subclass must do, without specifying all the implementation.

For example:

abstract class Bank {
    abstract int getRateOfInterest();
}

Here, Bank says: Every bank must provide getRateOfInterest(). But it does not specify the rate.

  • SBI decides: return 7;
  • PNB decides: return 8;

So in summary:

  • Bank → tells WHAT to do
  • SBI / PNB → tell HOW to do it

4. Use of Abstract Method

An abstract method is used when the parent class knows that a method is required, but it does not know the exact implementation.

Example:

abstract class Bank {
    abstract int getRateOfInterest();
}

Here, abstract int getRateOfInterest(); is an abstract method.

It consists of:

  • return type → int
  • method name → getRateOfInterest
  • no body (No implementation details inside {})
From the lab book: An abstract method is a method having no definition, where the definition is provided by the subclass.

5. Why do we use an Abstract Method?

Suppose different banks have different interest rates.

  • SBI → 7%
  • PNB → 8%

If we write:

abstract class Bank {
    abstract int getRateOfInterest();
}

We are essentially saying:

"Every bank must have a method to return its interest rate, but each bank can implement it differently."

This flexibility and enforcement is the main purpose of an abstract method.
