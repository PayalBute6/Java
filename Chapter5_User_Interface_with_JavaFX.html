Chapter 5: User Interface with JavaFX

5.1 Introduction

JavaFX is a Java-based platform used to develop graphical user interface (GUI) applications. It provides tools and libraries for creating interactive desktop applications with text, buttons, images, charts, animations, and other visual elements.

JavaFX is also known as OpenJFX in its open-source form.

A Graphical User Interface (GUI) allows users to interact with an application through visual controls (such as buttons, text boxes, and menus) instead of typing commands into a command-line terminal.

Common examples of GUI applications:

  • Login and registration forms
  • Student management systems
  • Billing applications
  • Banking applications
  • Data visualization dashboards

Rich Internet Applications (RIAs)

A Rich Internet Application (RIA) is an application that delivers a rich, responsive, and visually interactive user experience, similar to traditional desktop applications, but with modern multimedia, data visualization, and network connectivity capabilities.

JavaFX applications are classified as RIAs because they provide enhanced graphics, fast responsiveness, and interactive features compared with traditional static web pages.

In simple words, an RIA makes an application more interactive and convenient to use.

Characteristics of RIAs:

  1. Rich user experience: Provides interactive controls, high-resolution graphics, and smooth animations.
  2. Responsiveness: Responds quickly and smoothly to user actions without page reloads.
  3. Connectivity: Connects and communicates seamlessly with network-based web services, databases, and remote APIs.
  4. Rich graphics: Supports modern visual elements including vector graphics, images, audio, and video playback.
  5. Security: Protects user data and restricts unauthorized access through standard security models.
  6. Easy development: Reusable GUI components, layout containers, and styling engines simplify application creation.
  7. Cross-platform support: JavaFX applications run on Windows, macOS, and Linux when the JavaFX runtime is available.

5.2 What is JavaFX?

JavaFX is a modern Java library and GUI toolkit used to build rich client-side applications. It provides comprehensive facilities for creating windows, layouts, controls, graphics, animations, charts, and event-driven applications.

Why JavaFX?

  • It provides a modern alternative to older Java GUI frameworks such as AWT and Swing.
  • It supports reusable and customizable UI controls.
  • It provides flexible layout containers for arranging components automatically.
  • It includes built-in charting components for visual data representation.
  • It provides a powerful event-handling mechanism to respond to user actions.
  • It supports CSS-like styling for separating design from application code.
  • It runs across multiple desktop operating systems.

Features of JavaFX

  1. Rich set of APIs: Extensive built-in classes and methods for controls, layouts, shapes, media, and charts.
  2. Scene Builder support: A drag-and-drop visual design tool that generates FXML layout code automatically.
  3. FXML: An XML-based declarative markup language used to define user interfaces separately from Java business logic.
  4. CSS-like styling: Allows developers to style controls, fonts, colors, and backgrounds using familiar CSS syntax.
  5. Integrated graphics: Built-in 2D and 3D graphics capabilities, including shapes, gradients, and visual effects.
  6. Animation and multimedia: High-performance timeline animations, transitions, and audio/video playback engines.
  7. Event handling: Robust event system to handle mouse clicks, keystrokes, window events, and touch gestures.
  8. Layout management: Built-in layout containers such as HBox, VBox, BorderPane, GridPane, FlowPane, and StackPane.
  9. Built-in charts: Native charting library including Pie Chart, Line Chart, Area Chart, and Bar Chart.
  10. Cross-platform development: Applications written in JavaFX can run on any platform supported by Java and JavaFX.

5.3 Architecture of JavaFX

JavaFX architecture is layered to support the development of rich, cross-platform GUI and web applications. It is a complete software platform that allows developers to build various content-rich client applications that operate consistently across several platforms with high-performance graphics, multimedia, and UI controls.

Figure 5.1 shows the layered architecture of JavaFX, illustrating how the high-level application API connects with the internal rendering, windowing, and runtime engines.

1. JavaFX API

The JavaFX API is the top layer providing public classes and packages for animations, UI controls, CSS styling, scene graph, events, media, and application lifecycle. Important packages include:

  • javafx.animation: Contains classes to add transition-based animations such as fill, fade, rotate, scale, and translation to JavaFX nodes.
  • javafx.application: Contains a set of classes responsible for the JavaFX application life cycle (e.g., Application).
  • javafx.css: Contains classes to add CSS-like styling to JavaFX GUI applications.
  • javafx.event: Contains classes and interfaces to deliver and handle JavaFX events (e.g., ActionEvent, EventHandler).
  • javafx.geometry: Contains classes to define 2D objects, coordinates, insets, and alignments (e.g., Insets, Pos, Point2D).
  • javafx.scene: Contains the core classes for the scene graph, such as Scene, Node, Parent, and Group.
  • javafx.scene.control: Contains standard UI controls such as Button, Label, TextField, CheckBox, RadioButton, and ComboBox.
  • javafx.scene.layout: Contains container layout panes such as HBox, VBox, BorderPane, GridPane, FlowPane, and StackPane.
  • javafx.scene.chart: Provides built-in charting components including PieChart, LineChart, AreaChart, and BarChart.
  • javafx.stage: Contains top-level window container classes such as Stage and file dialogs.

2. Stage and Scene

  • Stage: Represents the top-level window of a JavaFX application (equivalent to a Frame in AWT/Swing). The primary stage is automatically created by the JavaFX runtime and passed to the start(Stage primaryStage) method.
  • Scene: Represents the container holding all physical visual content displayed inside a stage. A stage can display only one scene at a time, but scenes can be changed dynamically.

3. Scene Graph

The Scene Graph is a hierarchical, tree-like data structure of visual objects called nodes. Every visual element displayed on screen (layout container, button, label, shape) is a node in this tree:

  • Root node: The first and top-most container node added directly to the Scene (e.g., VBox, BorderPane, GridPane). It has no parent.
  • Branch node: An intermediate node that can contain child nodes (containers like HBox or StackPane).
  • Leaf node: A terminal node that cannot have children (controls such as Button, Label, TextField, or shapes like Circle, Rectangle).

 └── Scene (Content Container)
      └── VBox (Root / Branch Node)
           ├── Label (Leaf Node)
           ├── TextField (Leaf Node)
           └── Button (Leaf Node)

4. Quantum Toolkit

The Quantum Toolkit connects the higher-level JavaFX APIs and Scene Graph with the lower-level graphics (Prism) and windowing (Glass) engines. It acts as the coordinator between the JavaFX Application Thread (which handles user events and updates the scene graph) and the Render Thread (which draws pixels via Prism), ensuring smooth performance and thread safety without stuttering.

5. Prism (JavaFX Graphics Engine)

Prism is the high-performance, hardware-accelerated graphics rendering system in JavaFX. It renders both 2D and 3D graphics by communicating with native graphics hardware acceleration libraries:

  • Uses Direct3D (D3D) on Microsoft Windows.
  • Uses OpenGL on macOS and Linux platforms.
  • If dedicated hardware acceleration is unavailable, Prism automatically falls back to a software rendering pipeline (Java 2D).

6. Glass Windowing Toolkit

The Glass Windowing Toolkit is a platform-dependent layer that provides low-level windowing and event management. It interfaces directly with native operating system window managers:

  • Win32 on Windows
  • GTK+ on Linux
  • Mac OS X Cocoa on macOS

Glass is responsible for creating native windows, dispatching mouse and keyboard input events from the operating system to JavaFX, and managing native system timers.

7. WebView & WebKit

WebView is an embedded web component powered by the open-source WebKit browser engine. It allows developers to embed full HTML5 web pages, execute JavaScript, apply CSS styles, and navigate web links directly inside a JavaFX desktop window.

8. Media Engine & GStreamer

The Media Engine provides audio and video playback capabilities in JavaFX applications. It is powered by the GStreamer multimedia framework, supporting audio and video streaming, media controllers, and playback of supported multimedia formats.

9. JDK APIs, Tools, and Java Virtual Machine (JVM)

At the base of the architecture sits the Java Development Kit (JDK) and the Java Virtual Machine (JVM). They provide the execution environment, memory management, garbage collection, and core libraries (collections, I/O, concurrency) that allow JavaFX to run seamlessly across all supported platforms.

5.4 Life Cycle of a JavaFX Application

A JavaFX application entry class must extend the abstract class javafx.application.Application. The JavaFX runtime manages the application through three distinct lifecycle methods executed in a predefined order.

Three Important Life-Cycle Methods

Method Description Stage Available?
public void init() Called first before the UI is loaded. Used to initialize background data, load files, and perform setup. No (Cannot create UI components here)
public abstract void start(Stage primaryStage) Main entry point for building and displaying the GUI. Must be overridden. Receives the primary stage created by the runtime. Yes (Main UI configured and displayed here)
public void stop() Called automatically when the application terminates (e.g., when the last window closes). Used to close database connections and release resources. No (Cleanup phase)

Life-Cycle Execution Flow

The life cycle of a JavaFX application describes the exact sequence of events from the moment the program begins until it terminates. The JavaFX runtime manages this lifecycle across different specialized threads (the Launcher Thread and the JavaFX Application Thread).

Detailed Step-by-Step Execution Sequence

  1. Application Launch: The program starts in the standard public static void main(String[] args) method. It calls Application.launch(args), which bootstraps the JavaFX runtime system.
  2. Application Instance Creation: The JavaFX runtime automatically instantiates the specified Application subclass using its default no-argument constructor before calling any lifecycle methods.
  3. Initialization Phase — init(): The runtime invokes init() on the JavaFX-Launcher thread before any graphical window is created. This method is optional and is used to load configuration files, parse parameters, or establish network connections. Note: Attempting to construct a Scene or modify a Stage here will cause an exception.
  4. UI Construction Phase — start(Stage primaryStage): The runtime switches to the JavaFX Application Thread and calls start(primaryStage). This is the only abstract method in Application and must always be overridden. The primary stage is passed as a parameter. Here, controls (buttons, labels) and layouts are added to a Scene, attached to the stage via primaryStage.setScene(scene), and displayed using primaryStage.show().
  5. Active Running Phase (Event Loop): The application enters the running state. The JavaFX Application Thread executes an internal event loop that listens for user actions such as mouse clicks, button taps, and keyboard inputs, dispatching them to registered event handlers.
  6. Shutdown Trigger (User Closes Window / Platform.exit()): The termination sequence is initiated when the user closes the last application window (or clicks the window close button [X]), or code explicitly invokes Platform.exit() or System.exit(0).
  7. Cleanup Phase — stop(): The runtime invokes stop() on the JavaFX Application Thread. This optional method is the designated location for releasing resources, saving user settings, writing pending data, and closing database or file connections.
  8. Process Exit: The JavaFX runtime finishes releasing native operating system windowing and graphics handles, shuts down all background threads, and terminates the JVM process.

Life-Cycle Methods Summary Table

Step # Phase / Method Execution Thread Must Override? Primary Stage Available? Main Responsibility
1 main() / launch() Main Thread Mandatory (to run) No Initializes runtime and begins application bootstrap.
2 Instance Creation JavaFX-Launcher Thread Automatic (calls constructor) No Constructs an instance of the Application subclass.
3 public void init() JavaFX-Launcher Thread Optional (default empty) No Non-GUI setup, background data loading, resource preparation.
4 public abstract void start(Stage) JavaFX Application Thread Mandatory (Abstract) Yes Constructs UI, scene graph, and shows the primary window.
5 Active Running (Event Loop) JavaFX Application Thread Automatic Yes Processes GUI events, animation timers, and user interactions.
6 Window Close / Platform.exit() User Action / Application Code Event Trigger Yes → Closing Initiates the application shutdown procedure.
7 public void stop() JavaFX Application Thread Optional (default empty) No (Stage closing) Cleanly releases resources, saves state, and closes connections.
8 Application Exit JVM / OS Automatic No Native resources freed; JVM process terminates.
Important Points on JavaFX Life Cycle:
  • Which method is abstract in Application? Only start(Stage primaryStage) is abstract. init() and stop() have default empty implementations.
  • Can we create UI components inside init()? No. UI components must be created and updated on the JavaFX Application Thread, not the Launcher thread.
  • Which thread executes start() and stop()? Both execute on the JavaFX Application Thread.
  • How to programmatically exit a JavaFX application? Call Platform.exit(), which cleanly invokes the stop() lifecycle method before closing.

Basic JavaFX Program: HelloJavaFX.java

import javafx.application.Application;
import javafx.stage.Stage;
import javafx.scene.Scene;
import javafx.scene.control.Label;
import javafx.scene.layout.StackPane;

public class HelloJavaFX extends Application {

    @Override
    public void init() {
        System.out.println("init() method called: Initializing resources...");
    }

    @Override
    public void start(Stage primaryStage) {
        System.out.println("start() method called: Building user interface...");

        // 1. Create a UI component (node)
        Label label = new Label("Welcome to JavaFX");

        // 2. Create a layout container and add the node
        StackPane root = new StackPane(label);

        // 3. Create a scene with dimensions (width: 400, height: 200)
        Scene scene = new Scene(root, 400, 200);

        // 4. Configure the stage
        primaryStage.setTitle("My First JavaFX App");
        primaryStage.setScene(scene);
        primaryStage.show(); // Display the window
    }

    @Override
    public void stop() {
        System.out.println("stop() method called: Cleaning up resources...");
    }

    public static void main(String[] args) {
        launch(args); // Launches the JavaFX application
    }
}

Detailed Program Explanation

  • extends Application: Inherits core JavaFX application functionality.
  • launch(args): Static method called from main() that initializes the JavaFX runtime and starts the lifecycle sequence.
  • start(Stage primaryStage): Abstract method that must be overridden; receives the application's main window (the primary stage).
  • new Label(...): Creates a read-only text control node.
  • new StackPane(label): Layout pane that places its children stacked at the center.
  • new Scene(root, 400, 200): Creates a scene containing the layout root with width 400 pixels and height 200 pixels.
  • primaryStage.setTitle(...): Sets the title displayed in the window title bar.
  • primaryStage.setScene(scene): Attaches the scene to the primary stage.
  • primaryStage.show(): Makes the stage visible to the user.
In modern Java (Java 11 and later), JavaFX is unbundled from the standard JDK. It is supplied as separate OpenJFX modules. When compiling and running via command line, you specify module paths: --module-path /path/to/javafx-sdk/lib --add-modules javafx.controls,javafx.fxml.

5.5 Common JavaFX Layouts

A layout container (or layout pane) automatically calculates the size and position of child nodes inside a scene. Instead of specifying manual pixel coordinates for every button and label, layout panes arrange components automatically according to specific rules and adapt when the window is resized.

HBox arranges its child nodes horizontally in a single row from left to right.

Practical Program: Login Form Using JavaFX

This program demonstrates how to combine labels, a text field, a password field, a button, and a layout container into an interactive form.

import javafx.application.Application;
import javafx.scene.Scene;
import javafx.scene.control.*;
import javafx.scene.layout.GridPane;
import javafx.stage.Stage;

public class LoginForm extends Application {

5.7 JavaFX Charts

JavaFX provides rich chart controls in the package javafx.scene.chart to visualize data graphically. Charts make it easy to spot trends, compare values across categories, and observe proportions.

The four primary chart types are:

  1. Pie Chart: Slices of a circle showing proportions of a whole (100%).
  2. Line Chart: Points connected by lines showing trends over time.
  3. Area Chart: Similar to a line chart, but the area below the line is colored/filled.
  4. Bar Chart: Rectangular bars showing categorical comparisons.

1. Pie Chart

A PieChart divides data into circular slices. Each slice's angle represents its proportion of the total sum.

Key Steps to Create a Pie Chart:

  1. Create data items using PieChart.Data(name, value).
  2. Collect the items into an ObservableList<PieChart.Data>.
  3. Create the PieChart object passing the list.
  4. Set titles and properties (e.g., setTitle()).
  5. Add the chart to a scene layout and display the stage.

Program: PieChartExample.java (Tata Motors Sales)

import javafx.application.Application;
import javafx.collections.FXCollections;
import javafx.collections.ObservableList;

import javafx.scene.chart.PieChart;
import javafx.scene.layout.StackPane;
import javafx.stage.Stage;

public class PieChartExample extends Application {

    @Override
    public void start(Stage stage) {
        // 1. Prepare data
        ObservableList<PieChart.Data> data =
            FXCollections.observableArrayList(
                new PieChart.Data("Nexon", 15),
                new PieChart.Data("Swift", 22),
                new PieChart.Data("Harrier", 12),
                new PieChart.Data("Safari", 25),
                new PieChart.Data("Altroz", 18)
            );

        // 2. Create chart
        PieChart pc = new PieChart(data);
        pc.setTitle("Tata Motors Sales");

        // 3. Add to layout and scene
        StackPane root = new StackPane(pc);
        Scene scene = new Scene(root, 600, 400);

        stage.setTitle("Pie Chart Example");
        stage.setScene(scene);
        stage.show();
    }

    }
}

2. Line Chart

A LineChart plots data points on a Cartesian coordinate plane (X-axis and Y-axis) and connects consecutive points with straight lines. It is ideal for showing trends over continuous intervals such as time, years, or dates.

Important Classes for Line Chart:

  • CategoryAxis: X-axis displaying string categories (e.g., years, months).
  • NumberAxis: Y-axis displaying numerical values.
  • LineChart<X, Y>: The chart container linking both axes.
  • XYChart.Series<X, Y>: A named set of data points.
  • XYChart.Data<X, Y>: An individual point (x, y).

5.8 Event Handling

What is an Event?

An event is an external occurrence or notification that something significant has happened in the application, usually triggered by user interaction or the system (such as clicking a button, typing a character, moving the mouse, or closing a window).

What is Event Handling?

Event handling is the programming mechanism that captures an event and executes a designated block of code (an event handler) in response to that event.

Important Event Handling Terms

  1. Event Source: The UI node that generates the event (e.g., a Button clicked by the user).
  2. Event Object: An instance of an event class (inheriting from javafx.event.Event) that stores information about the event (e.g., mouse coordinates, key code, target node).
  3. Event Target: The specific node in the scene graph at which the event is directed.
  4. Event Handler: The code or method implementation that processes the event and carries out the action. In JavaFX, event handlers implement EventHandler<T>.
  5. Event Registration: The act of connecting an event handler to a source node using methods such as setOnAction() or addEventHandler().

Phases of Event Handling (Event Dispatch Chain)

When an event occurs on a node, JavaFX processes it through four stages:

  1. Event Targeting: The initial target node (e.g., the clicked button) is determined. An event dispatch chain is constructed from the Stage down through the scene graph to the target node.
  2. Event Capturing (Top-down): The event travels downwards from the root node (Stage/Scene) down to the target node. Filters registered at parent nodes can intercept and consume the event before it reaches the child.
  3. Event Bubbling (Bottom-up): The event travels upwards from the target node back toward the root node. Parent nodes can inspect and handle the event as it bubbles up.
  4. Event Handling: Registered event handlers on the target node execute their logic.
           Stage (Top)
             │      ▲
             │      │
           Scene    │
             │      │
           VBox     │
             │      │
             ▼      │
        Button (Target)
   [Capturing Phase] [Bubbling Phase]
      (Top-down)       (Bottom-up)

Common Types of Events

Event Category Class Triggered By
Action Events ActionEvent Clicking a button, pressing Enter in a text field, selecting a menu item.
Mouse Events MouseEvent Clicking, dragging, pressing, moving, entering, or exiting a node.
Keyboard Events KeyEvent Pressing, releasing, or typing a key on the keyboard.
Window Events WindowEvent Showing, hiding, minimizing, or closing a Stage window.

Three Ways to Implement Event Handlers

Method 1: Using a Lambda Expression (Modern & Recommended)

Button button = new Button("Click Me");

button.setOnAction(e -> {
    System.out.println("Button Clicked using Lambda Expression");
});

Method 2: Using an Anonymous Inner Class

import javafx.event.EventHandler;
import javafx.event.ActionEvent;

Button button = new Button("Click Me");

button.setOnAction(new EventHandler<ActionEvent>() {
    @Override
    public void handle(ActionEvent e) {
        System.out.println("Button Clicked using Anonymous Class");
    }
});

Method 3: Using a Named Handler Method

Button button = new Button("Click Me");
button.setOnAction(e -> handleClick());

private void handleClick() {
    System.out.println("Button Clicked via Named Method");
}

Registering and Removing Event Handlers

Handlers can be registered directly with setOnAction() or the generic addEventHandler():

// 1. Generic registration
EventHandler<ActionEvent> handler = e -> System.out.println("Handled");
button.addEventHandler(ActionEvent.ACTION, handler);

// 2. Removing the registered handler
button.removeEventHandler(ActionEvent.ACTION, handler);

// 3. Clearing handler registered via setOnAction
button.setOnAction(null);

Mouse and Keyboard Event Handling

Mouse Event Example:

Button button = new Button("Mouse Target");

button.setOnMouseClicked(e -> {
    System.out.println("Mouse clicked at: (" + e.getX() + ", " + e.getY() + ")");
});

Keyboard Event Example:

Scene scene = new Scene(root, 400, 200);

scene.setOnKeyPressed(e -> {
    System.out.println("Key pressed: " + e.getCode());
});
Important Note on Keyboard Events: A node must have keyboard focus to receive keyboard events. Scenes receive keyboard events when no specific child node consumes them.
